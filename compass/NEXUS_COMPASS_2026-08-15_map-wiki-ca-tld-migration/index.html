    3. NEXUS CA — CERTIFICATE AUTHORITY (step-certificates)¶

    What: Initialized a proper internal Certificate Authority using Smallstep step-ca. Replaces all self-signed certs across NeXuS. First cert issued to nexus-web-server.

    CA Details¶

    Item Value
    CA Name NeXuS CA
    CA Address 127.0.0.1:9000
    Root fingerprint 99f17400023e289fee7bac581a2f4f0178dd63f9a16f59d8fef97cfd3132f22d
    SANs localhost, local.host.local, 127.0.0.1, 192.168.1.15
    Root cert validity 2026 → 2036 (10 years)
    Provisioner nexus (JWK) + ACME
    Max cert duration 8760h (1 year)
    Default cert duration 2160h (90 days)

    File locations (under ~/NeXuS/ TLD)¶

    ~/NeXuS/data/step-ca/
  config/
    ca.json              ← CA config
    defaults.json        ← client defaults
  certs/
    root_ca.crt          ← ROOT — import this to trust NeXuS certs
    intermediate_ca.crt  ← intermediate
  secrets/
    root_ca_key          ← encrypted root key
    intermediate_ca_key  ← encrypted intermediate key
  db/                    ← badger cert database

~/NeXuS/secrets/
  nexus-ca.passwd        ← CA password (chmod 600)

    First cert issued¶

    ~/NeXuS/Projects/nexus-web-server/
  cert.pem    ← signed by NeXuS CA Intermediate CA
  key.pem     ← ECDSA P-256, chmod 600
    Valid: 2026-08-16 → 2027-08-16 Subject: local.host.local + SANs: localhost, 127.0.0.1, 192.168.1.15

    Start the CA¶

    STEPPATH=~/NeXuS/data/step-ca step-ca \
  ~/NeXuS/data/step-ca/config/ca.json \
  --password-file ~/NeXuS/secrets/nexus-ca.passwd

    Issue a cert for any new project¶

    STEPPATH=~/NeXuS/data/step-ca \
step ca certificate "<project-name>" \
  ~/NeXuS/Projects/<project>/cert.pem \
  ~/NeXuS/Projects/<project>/key.pem \
  --ca-url https://127.0.0.1:9000 \
  --root ~/NeXuS/data/step-ca/certs/root_ca.crt \
  --provisioner nexus \
  --provisioner-password-file ~/NeXuS/secrets/nexus-ca.passwd \
  --san localhost --san 127.0.0.1 --san local.host.local \
  --not-after 8760h

    Trust the root cert (run in terminal with TTY)¶

    doas cp ~/NeXuS/data/step-ca/certs/root_ca.crt /usr/local/share/ca-certificates/nexus-ca.crt
doas update-ca-certificates
    Firefox: Settings → Privacy → Certificates → View Certificates → Import → root_ca.crt

    4. TLD MIGRATION DECISION¶

    Decision: All NeXuS projects live under ~/NeXuS/Projects/project/. Personal files (Pictures, Music, Documents) stay in XDG dirs.

    Canonical structure¶

    ~/NeXuS/                          ← NEXUS_HOME — everything NeXuS
  Projects/                       ← NEXUS_PROJECTS — code, apps, repos
    nexus-web-server/
      nexus_web_server.py
      cert.pem  key.pem           ← own cert (no sharing)
      dist/                       ← own static root
      .local.env                  ← own local config
      docs/action_report.md
    nexus-portal/
    nexus-nncc/
    ...
  scripts/                        ← NEXUS_SCRIPTS (migrating from ~/scripts/)
  timeline/                       ← already here ✓
  characters/                     ← already here ✓
  secrets/nexus.env               ← shared API keys (ONLY shared resource)
  data/                           ← runtime data (step-ca, nncc, etc.)
  museum/                         ← fossil repos (migrating from ~/museum/)
  docs/
~/Pictures/                       ← XDG — stays here
~/Music/                          ← XDG — stays here
~/Documents/                      ← XDG — stays here

    The three rules (non-negotiable)¶

    1. No script contains a path — reads $NEXUS_* vars with sane defaults
    2. No app contains a path — reads env vars; defaults to ~/NeXuS/…
    3. Projects are sealed — everything a project needs lives inside it; projects communicate via APIs and env vars only, never by reading each other's files

    The portability test¶

    Can you mv ~/NeXuS/Projects/nexus-web-server /tmp/ and run it from there by setting one env var? If yes — portable. If no — something is hardcoded.

    7. PRIVACY PROXY RESEARCH¶

    The user was looking for a proxy that strips passwords, API keys, and self-identifying info from outgoing traffic.

    mitmproxy — identified as the tool. Intercepts HTTPS, runs Python addons on every request/response. Write the scrubbing logic, it handles the intercept. Ready-made addons for API key stripping on GitHub.

    PrivAiTe (github.com/crp4222/PrivAiTe) — LLM-specific proxy. Reversibly redacts PII before prompts reach external APIs. marie@acme.com → <EMAIL_ADDRESS_1> on the wire, restored in response. API keys redacted irreversibly on purpose. Uses Presidio + OpenAI privacy-filter model.

    The NeXuS approach: The web server at :8443 already intercepts every LLM call via /api/llm. Presidio or a custom scrubber inserted into _llm_proxy() would cover all apps simultaneously. One place, all apps protected.

    Privoxy can also do this via +filter action rules for regex patterns (API keys, emails, auth headers) — already deployed in the darknet stack.
