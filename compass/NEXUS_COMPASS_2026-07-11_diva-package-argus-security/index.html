    A. ARGUS ACCOUNTABILITY — 🔵 DESIGNED (spec not yet written to a doc; captured in memory)¶

    The mandate (Anon): "Accountability with a cryptographical fingerprint, and everything in NeXuS is a transaction so every transaction will have every fingerprint that touched it."

    CIA triad, NeXuS meaning: C=Confidentiality · I=Integrity · A=Accountability (NOT Availability; Availability = "YMC-Availability").

    Architecture (all Alpine-repo tools, nothing hand-rolled): - git = the ledger. Every doc/edit/backup = a signed commit. Parent-hash chain = the tamper-evident fingerprint chain. Do NOT build a bespoke PKI/JSONL ledger. - SSH Ed25519 keys = entity identities. git config gpg.format ssh + commit -S + allowed_signers. - Master/child model: ONE master key, password-protected, offline. Master ISSUES children (DERIVED, not certified — chosen because master = sovereign root). One child per entity (anon, claude, eye-sky, node-argus). Only master revokes. Delete = revoke (append, never erase). - KeePass KDBX v2 = vault; Rook (Alpine pkg, sr.ht/~ser/rook) = headless Secret Service serving keys (no GUI). - Keybase sigchain = the pattern we copy, NOT a dependency (Keybase = frozen since Zoom acquisition — the lock-in cautionary tale). - Separate from Ghost Gate key (Ghost Gate = external Nostr kind-24000 receipts). - Two-tier signing: (1) provenance = every op self-signs (frictionless); (2) multi-sig threshold = privileged only (merge to main, backup restore, archive, key changes). - Open integration detail: how Rook (Secret Service = passwords) feeds git's SSH signer (agent vs stored key). Small, testable.

    Full detail: memory project_argus_accountability.md.

    B. WATCHER TAKEDOWN + EMERGENCY STOP LAW — ✅ DONE¶

    • nexus-tmux-watch.sh was a false-positive machine: it flagged our OWN tmux status-bar scripts (continuum_save.sh, ram_info.sh, cpu_info.sh, uptime.sh) as "🔴 UNKNOWN PID ON SOCKET." Log: ~/logs/nexus-tmux-watch.log (25 "alerts" in an hour, all benign).
    • It kept "respawning" because it backgrounds its workers (monitor_loop &, inotifywait … &, line 55/113) → they orphan to PPID 1 and survive killing the launcher. Not resurrection — detached daemons.
    • Killed by exact PID (ps/awk), NOT pkill -f — pkill -f "nexus-tmux-watch" matches our own shell's command line and SIGKILLs it (that was the exit 1/144 bug).
    • Definitive fix: archived the executable → ~/scripts/archive-disabled-2026-07-11/nexus-tmux-watch.sh. Now test -x fails everywhere; no config/orphan can relaunch it. (Line still lives in the sacred backup ~/.config/tmux/org-2026-07-07-tmux.conf:140 but that config isn't sourced and the executable is gone.)
    • Why "why now?" The watcher was only ~5 min old — alerts track the WATCHER'S uptime, not an attacker's arrival. Status bar was always benign; the observer just woke up.

    ⚖️ EMERGENCY STOP LAW (established this session, in memory feedback_nexus_rules): No power-script (watcher/lockdown/hooks) ships or activates without a working, independent kill switch — preferably a tmux keybinding that nukes hooks + PIDs in one shot. No kill switch = feature doesn't ship.
