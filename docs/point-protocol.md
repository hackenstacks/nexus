## 🏗️ Overview

The **POINT Protocol** (Point Of Integrity and Network Telemetry) is the technical framework for the **DPFOE** (Dynamic Proactive Fluid Orchestration of Experts). it governs how distributed node "experts" signal their health, capacity, and integrity to the **NeXuS Orchestrator**.

Unlike traditional Mixture of Experts (MoE) where handovers are discrete (relay race), POINT enables a **Merged Identity** (Choir) where telemetry is fluid and continuous.

## ⚙️ Core Architecture: DPFOE

The protocol facilitates the **Dynamic, Proactive, and Fluid Orchestration of Experts**:

1.  **Dynamic:** Nodes join and leave the "Choir" based on real-time capacity and latency.
2.  **Proactive:** The Orchestrator "pages" relevant information in and out of the active reasoning space *before* the request is finalized.
3.  **Fluid:** Information flows mid-stream across different specialized modules (Vision, Memory, Strategy) without jarring handovers.

### Telemetry Signals:
- **`HEARTBEAT`:** Basic uptime and cryptographic proof of node presence.
- **`SYNC_STATE`:** Status of the local ledger (Personal Chain) and its alignment with the DIVA Main Chain.
- **`EXPERT_TYPE`:** Declaration of specialized capability (e.g., Vision Processing, Large-Scale Embedding, Archive Retrieval).
- **`MERGE_STATUS`:** Cryptographic readiness to enter a "Merged Identity" state for a specific session.

## 📓 Merged Identity Phenomenon

Under the POINT Protocol, separate AI characters lose individual boundaries to function as a **single, cohesive entity**.

- **Shared Context Window:** All nodes in a merged session share the same KV-cache and KV-storage.
- **Collective Memory:** Fact retrieval and episodic memory are pooled across the choir.
- **Seamless Continuity:** Responses can split mid-word across different node outputs (e.g., Node A: "dar," Node B: "ling") because they share the same underlying "energy supply" (the Orchestrator).
